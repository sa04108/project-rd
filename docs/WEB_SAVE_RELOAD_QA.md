# Web 저장 복원 검사 수정 · 2026-10-03 (한국시간)

## 확인한 오류와 수정

사용자 실행 [37032854168](https://github.com/sa04108/project-rd/actions/runs/37032854168)은 `main`의 `3624014`에서 Web export까지 성공했고 브라우저 새로고침 이후 저장 필드 비교에서 실패했다. 이전 같은 게임 코드의 실행은 통과했으며, 원래 오류에는 어느 필드가 달랐는지 기록되어 있지 않았다.

Godot 4.7.2의 `OS_Web::main_loop_iterate()`는 파일 기록 후 다음 루프에서 비동기로 IndexedDB 동기화를 시작한다. `FileAccess.flush()`와 파일 존재 확인은 메모리 파일시스템에 대한 결과이며 영구 기록 완료를 뜻하지 않는다. 새 검사로 실행했을 때도 메뉴에 도착한 뒤 실제 기록 확정까지 추가 1,590ms가 필요했다. 이는 기존 검사의 완료 시점 가정에 문제가 있음을 입증하지만, 원래 실행의 필드별 원인을 소급해서 단정하지는 않는다.

QA 브리지는 메뉴에 읽힌 전체 저장 스냅샷과 프로필을 제공한다. 브라우저 검사는 읽기 전용 IndexedDB 트랜잭션으로 격리된 QA 저장만 읽고, 실행 ID·적·용병·난수 상태를 포함한 전체 스냅샷 및 프로필이 일치하는지 최대 20초 동안 확인한다. 직접 동기화하거나 저장을 덮어쓰지 않는다. 이후 기존 새로고침 비교를 유지하면서 부팅 후 읽은 전체 스냅샷·프로필 비교도 추가했다. 불일치 시 기대값·실제값과 마지막 관측 상태를 기록한다.

CI는 Playwright 1.57.0이 설치한 Chromium을 명시적으로 사용한다. 실행기에 우연히 설치된 다른 Chromium을 선택하지 않는다. 모든 브랜치 push는 검사하며, `main` push와 수동 실행은 검사 통과 후 배포한다. 브랜치 검사가 다른 브랜치의 배포를 취소하지 않도록 동시 실행 그룹을 분리했다.

실제 배포 작업에는 별도의 공통 Pages 동시 실행 그룹을 유지해 `main`과 수동 브랜치 배포가 동시에 실행되지 않게 했다. IndexedDB 요청 자체가 막히는 경우에도 전체 대기 시간을 넘지 않도록 타이머를 적용하며, 실패 후 브라우저를 닫아 보류 중인 읽기를 정리한다.

## 범위와 한계

게임 규칙, 저장 형식, 일반 사용자의 저장 동작은 변경하지 않았다. 일반 UI에 영구 저장 완료 표시를 추가하거나 저장 직후 탭 종료를 보장한 변경이 아니다. 이는 [남은 작업](REMAINING.md)에 명시한다. 공개 배포에는 저장소 Pages의 최초 활성화가 필요하다. 원격 빌드 통과와 공개 URL 검증은 구분한다.
