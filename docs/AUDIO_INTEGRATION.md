# 사운드·진동 연결

샘플 비교는 [미리듣기](audio-samples.html), 생성 방식과 규격은 [샘플 기록](AUDIO_SAMPLES.md)을 참고합니다.

`game/audio_director.gd`가 음악 1개, UI 1개, 공격음 최대 3개의 플레이어를 관리합니다. 배경음악과 효과음 음량은 독립적이며 0은 재생을 중단합니다. 음악은 전투와 설정의 미리듣기에서만 재생되고, 앱이 배경으로 가면 일시정지됩니다. 기본값은 음악 35%, 효과음 65%, 진동 꺼짐, 음악 01, UI 01입니다. 설정 화면에서 세 음악과 세 UI 음색을 직접 바꿀 수 있습니다.

공격음은 기존 `attack_presented` 신호를 이용합니다. 표현 전용 난수로 피치를 최대 ±3% 바꾸며 전투 RNG에는 접근하지 않습니다. 실제 시간으로 전체 160ms, 같은 분류 320ms 간격을 두어 배속·밀집 상황에서도 재생량을 제한합니다. 버튼의 행동 결과에 별도 비프음을 겹치지 않습니다.

| 기존 공격 연출 | 공유 공격음 |
| --- | --- |
| slash, thrust | blade · 검/창 |
| bow, javelin | bow · 활/투창 |
| strike, slam | blunt · 타격/둔기 |
| cast, breath, lob | magic · 마법/브레스/투척 마법 |
| shot | shot · 총기 |

진동 강도 요청값은 0.45로 고정합니다. 꺼짐→켜짐 때 100ms, 목숨이 줄 때 35ms, 진행 중→클리어 때 320ms만 요청합니다. 동시에 몰린 목숨 감소는 150ms 안에서 합쳐 긴 진동이 되지 않도록 했습니다. 로드·재시작·설정 화면 재개방·패배·일반 클릭·공격에는 진동이 없습니다. 설정 파일 복원은 켜기 동작으로 취급하지 않습니다.

Android 내보내기에 VIBRATE 권한을 추가했습니다. Godot `Input.vibrate_handheld`를 사용하며 운영체제·브라우저·장치가 강도나 길이를 지원하지 않으면 실제 반응이 다를 수 있습니다. 데스크톱에는 진동을 요청하지 않습니다. 실제 Android/iOS 장치의 감각과 Web의 진동 지원 여부는 별도 기기 검증이 필요합니다.

기존 schema 1 프로필은 음악·효과음·기록을 보존하고 새 필드만 기본값으로 보완합니다. 잘못된 새 값은 기존 손상 파일 격리 절차를 따릅니다.

```bash
VERIFY_VISUAL=1 bash scripts/verify.sh
```

검증은 기존 게임·저장·생명주기·애니메이션 검사에 오디오 리소스 디코드, 독립 음소거, 재생 제한, 실제 공격 신호 연결, 진동 조건/중복 억제, 설정 터치·저장 검사를 추가합니다. 헤드리스 검사는 청감이나 물리 진동을 검증하지 않습니다.

2026-10-03 검증: `VERIFY_VISUAL=1 bash scripts/verify.sh` 종료 코드 0. 계약·저장 38개, 오디오·진동 30개, 개별 애니메이션 7개, UI 입력 269개가 통과했으며 import·생명주기·메인 300회 실행도 통과했습니다. 생성된 설정 화면 PNG를 확인했습니다. 모든 샘플의 디코딩·SHA-256·크기·클리핑·반복 경계를 별도로 확인했습니다. 실제 장시간 청취와 기기 진동은 수행하지 않았습니다.
