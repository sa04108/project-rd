# 게임 규칙

현재 유효한 요구와 구현 계약이다. 변경 이력은 Git, 미결 항목은 [REMAINING](REMAINING.md), 개별 능력치와 레시피는 [data/](../data/)에서 관리한다. 최신 사용자 지시가 우선하며, 리소스 그림이나 직업명만으로 게임 규칙을 추가하지 않는다.

## 기준과 범위

[game_rules.json](../data/game_rules.json)의 구분을 유지한다. **F**는 사용자 확정 요구, **I**는 좌표·일정 등의 구현 해석, **D**는 채택한 작업 기본안, **T**는 튜닝 수치다. F를 임의 변경하지 않는다. I 변경은 동등성을 검증하고, D/T 변경은 의도·영향·회귀 근거를 커밋에 남긴다. T에 저장돼 있어도 사용자가 지정한 목표·범위는 최신 지시를 따른다.

- 화면 표시 제목의 단일 원본은 `project.godot`의 `presentation/display_name` 설정이다. 메뉴 제목·창 제목·푸터의 표시 문구와 저장 식별자는 분리한다. 표시 변경을 이유로 `application/config/name`, Android 패키지 ID, 저장 경로·스키마를 바꾸지 않는다.
- 세계 각지의 용병이 모이는 길드와 클래식 하이 판타지가 배경이다. 익숙한 판타지와 영웅 서사, 직업을 알아보기 쉬운 장비, 약한 도트 느낌의 2D 원화를 사용한다. 세로·고정 정투영 카메라로 건물·격자에 원근 축소를 넣지 않는다.
- 핵심 루프는 골드 획득 → 무작위 1성 소환 → 조합 → 재배치·강화·군중제어 → 100웨이브 마왕 처치다.
- 현재 범위는 오프라인 게임, 로컬 영구 성장·다이아몬드, Web 공개 플레이와 내부 Android 디버그 검사다. 출시 서명·스토어 등록, 서버·계정·멀티플레이·랭킹, 실제 결제·광고, 에너지·출석 보상, 5성, C# 전환은 포함하지 않는다. 로컬 다이아몬드는 기기 저장값이며 유료 재화나 서버 검증 잔액으로 취급하지 않는다.
- 개별 캐릭터 원화와 고유 애니메이션을 사용하고, 아직 없는 동작은 명시적인 원화/공유 계열 대체 경로를 사용한다. 제작 완료 범위는 런타임 인덱스로 확인한다.

## 전장·배치

- 아군은 6열×6행, 총 36칸에 한 명씩 배치한다. 정수 칸 번호는 `열 * 6 + 행`이며 열·행은 0부터 센다. 빈칸은 왼쪽 열 위→아래, 다음 열 순서로 찾는다.
- 지면의 아군 영역은 `[0,6]×[0,6]`, 칸 중심은 `(열+0.5, 행+0.5)`다. 각 변에 폭 1칸의 적 통로를 두어 전체 범위는 `[-1,7]×[-1,7]`, 총 8×8단위다. 아군은 통로에 배치할 수 없다.
- 적 경로 중심선은 `(-0.5,-0.5) → (-0.5,6.5) → (6.5,6.5) → (6.5,-0.5) → (-0.5,-0.5)`, 한 변 7/전체 28단위다. 북서쪽(10시 방향) 성문 하나에서 아래로 출발해 반시계 방향으로 돌아 같은 성문을 지나 계속 순환한다. 한 바퀴마다 초과 이동량을 보존해 진행도를 0~28 사이로 되감으며, 탈출이나 목숨 차감은 없다. 카탈로그의 한 바퀴 이동 시간과 이동 속도는 유지한다.
- 화면 기준은 720×1280이다. 아군 영역은 화면 `(126,382)`에서 시작하는 468×468 영역이며 모든 칸과 적 통로 기준 폭은 78px다. 보드 내부 원점은 `(126,158)`, 보드 화면 위치는 `(0,224)`다. 두 축에 같은 배율을 사용하고 마주 보는 길 기준선을 평행하게 유지한다. 풀·흙 경계의 셰이더 혼합은 이 정투영 기준에만 장식을 더하며 거리 판정이나 RNG를 바꾸지 않는다.
- 용병은 한 칸을 충분히 채우도록 크게 표시하되 논리 점유·사거리·타격 판정은 지면 칸 중심을 사용한다. 사거리는 소수점 한 자리를 표시하고 화면 픽셀·발 표시 오프셋·무기 끝을 판정에 사용하지 않는다.
- 용병을 탭하면 해당 용병을 선택하고 위치를 바꾸지 않는다. 빈 칸 또는 용병 선택이 아닌 곳을 단순 클릭하면 선택을 해제하며, UI 콜백을 처리한 뒤 해제한다. 드래그·취소 입력은 선택을 유지한다. 전투 중 이동·점유 칸 교환은 드래그로만 한다. 배치 격자와 목표 칸까지의 노란 점선 화살표는 용병 드래그 중에만 나타난다. 선택 시 원형 사거리를 표시하고 선택이 없으면 정보 패널을 숨긴다. 이동·교환은 공격 타이머를 초기화하지 않으며 같은 칸 이동은 무변경이다.
- 화면 밖·외곽·팝업으로 가린 곳에 놓으면 이동을 취소한다. 팝업 밖에서 시작한 드래그도 팝업 위에서 끝나면 취소한다. 드래그 자동 조합과 적 추격은 없다.

## 전투·시간·웨이브

- 적은 아군을 공격하지 않는다. 아군 HP·피격·사망·부활·탱킹과 방어력 UI/강화는 없다. 사제 역할도 데이터에 정의한 지원 효과를 따른다. 적의 내부 피해 경감은 별도 설계이며 아군 방어력 UI를 되살리는 근거가 아니다.
- 사거리 안에서 진행도가 가장 큰 적을 먼저 공격하고 동률은 안정적인 개체 ID 순으로 정한다. 거리 비교는 `distance <= range`다. 아군 경계에는 공격을 막는 벽이 없다.
- 둔화는 유효한 효과 중 가장 강한 것을 사용하며, 강한 효과가 끝나면 남은 약한 효과로 돌아간다. 기절은 가장 늦은 만료를 유지한다. 마왕도 동일하게 군중제어를 받는다.
- 시뮬레이션은 최대 1/30게임초 소단계로 진행한다. 웨이브·생성·이동·공격·군중제어·쿨타임은 같은 게임시간을 사용한다. 표시용 투사체나 공격 준비 동작이 피해를 지연하거나 전투 RNG를 소비하지 않는다.
- 기본 배속은 ×1·×2다. ×3·×5·×10·×15·×20은 각각 정상 전투의 10·20·40·60·80웨이브 보스를 처치한 뒤 다이아몬드 100·200·300·600·1000개로 순차 구매한다. 웨이브 도달만으로는 해금되지 않는다. 전투 시작 뒤 실제 시간 5초 동안은 적 없이 배치 준비를 하며, 이 구간에는 전투 시간이 흐르지 않는다. 수동 정지는 전투 진행과 게임 입력을 막고 중앙에는 일시정지 아이콘만 표시하며 화면 어디든 한 번 탭하면 해제한다. 설정 창과 백그라운드 상태는 별도 정지 사유가 아니다. 단조 시계로 실제 경과시간을 한 번 계산하므로 OS/브라우저가 프레임을 멈춘 뒤 복귀하면 그 사이 시간도 전투에 반영한다. 앱 프로세스가 종료된 동안의 오프라인 진행은 없다.
- 1~99웨이브는 각각 30게임초로 고정된다. 일반 웨이브는 시작 후 0~9초에 한 마리씩 총 10마리, 기본 한 바퀴 이동 시간은 18초다. 일반 적은 처치될 때까지 남는다. 처치·생존 여부로 다음 웨이브 시간을 바꾸지 않는다.
- 10~90의 10배수 웨이브는 보스 한 마리만 시작 시 생성하고 한 바퀴 이동 시간은 27초다. 100웨이브는 마왕 한 마리이며 한 바퀴 이동 시간은 30초다. 모든 보스·마왕은 등장 웨이브의 명목 시작부터 60게임초 안에 처치해야 한다. 기한 판정은 다음 웨이브 전환보다 먼저 처리하므로, 10웨이브 보스의 기한 패배는 항상 11웨이브에 확정되고 12웨이브 생성은 없다. 이전 일반 적·기한이 남은 특수몬스터는 남을 수 있다.
- 100웨이브는 정상 진행의 2970게임초에 시작한다. 101웨이브와 수동 스킬은 없다. 보스·특수몬스터의 제한시간은 `F.enemy_timeout_seconds`(60)를 사용하며, 배속과 수동 정지에 따른 게임시간을 따른다. 배속·프레임 지연에도 생성 사건을 건너뛰거나 중복 처리하지 않는다.

## 거래·조합·보상형 적

- 시작 용병은 0명, 골드는 150에 영구 초기 골드 보너스를 더한다. 일반 소환은 무작위 1성이며 비용은 `50 + 이번 전투의 성공한 유료 소환 횟수 × 10`골드다(50→60→70…). `T.summon_cost`와 `T.summon_cost_step`이 시작 비용과 증가량의 단일 원본이다. 소환 실패·무료 추가 소환·도박·조합은 횟수를 늘리지 않으며 이미 나온 용병을 조합·배치·강화해 활용한다. 횟수는 이어하기에서 유지하고 새 전투에서 초기화한다. 골드·용병·강화는 이번 판에만 속한다.
- 비용·빈칸·재료·타깃·종료 상태를 거래 전에 검증한다. 잘못된 거래는 자원·개체·RNG를 바꾸지 않는다. 36칸이 차면 소환·도박은 막지만 재료 소비로 공간을 만드는 조합은 허용한다.
- 용병 하나당 조합법은 정확히 하나이며, 2~4성 28종 각각에 고정된 ID·수량의 재료식을 제공한다. 재료 수는 레시피마다 2~3명이고 여러 하위 성급을 함께 요구할 수 있다. 조합은 수동·무료이며 무작위 합성·판매·순환 조합은 없다. 기존 34종의 디자인·능력치·ID는 유지한다.
- 모든 1성·2성은 같은 종류 2~3명을 사용하는 상위 조합 경로가 있다. 혼합 재료식을 포함한 모든 경우를 검사하면 조합할 수 없는 1성은 최대6명, 2성은 최대10명이므로 **1·2성이 합계17명 이상이면 반드시 조합 가능**하다. 6×6에서 저성급만으로36칸이 막히는 상황을 해소한다. 3·4성을 많이 보유하거나 지원 용병을 보존하기 위해 가능한 조합을 선택하지 않는 경우까지 무제한 공간을 보장하지는 않는다.
- 선택한 기준 재료 칸에 결과를 두고 다른 재료 칸을 비운다. 기준이 없으면 열 우선 첫 재료 칸을 사용하며, 동일 후보는 칸/ID 순으로 선택한다. 실행 시 재검증하고 부분 소비나 같은 개체의 중복 소비를 허용하지 않는다.
- 강화는 1~4성 각각의 공통 공격력 네 항목이다. 현재·미래 용병에 적용하며 조합 결과에는 결과 성급의 강화만 적용한다. 첫 강화 가격은 성급별40·80·240·320골드이고 다음 가격은 기본값×(현재 강화 단계+1)이다. 공격 증가량은 단계당18%, 최대10단계다. 새로 소환·도박한 같은 성급에도 적용하고 CC·오라 수치는 강화하지 않는다. 기존 단계와 과거 지출은 보존하며 다음 구매부터 현행 가격을 쓴다. 가격·확률·증가량 등 튜닝은 정의 데이터와 UI를 함께 반영한다.
- 도박은 2성·3성 도전으로 나뉜다. 성공 풀에는 해당 성급의 모든 등록 용병을 포함한다. 유효한 도박 실패는 비용이 소모되고 보상이 없으며 거래 결과의 `ok=true, won=false`로 구분한다. 환급·하위 성급 보정 보상을 추가하지 않는다.
- 영구 성장은 메뉴에서 다이아몬드로 구매하며 다음 새 전투부터 적용한다. 이어하기는 스냅샷에 저장된 구매 당시 능력 단계와 전투 상태를 그대로 사용한다. 성급별 공격력은 단계마다 2%씩, 최대 40%까지 오른다. 2·3성 도박 확률은 각각 최대 10%p, 추가 소환 확률은 5%에서 시작해 단계마다 1%p씩 최대 14%까지 오른다. 시작 골드는 단계마다 10, 최대 100 증가한다. 배속은 위의 보스 처치·다이아몬드 구매 조건을 모두 충족해야 한다. 구버전에서 구매한 ×10·×15·×20 권리는 유지하며 이미 소유한 하위 배속을 다시 구매하지 않는다. 목숨과 추가 목숨 구매는 제거했다. 기존 `extra_lives` 단계·구매 원장·잔액은 저장 호환을 위해 보존하지만 효과를 적용하거나 신규 구매를 허용하지 않는다. 비용·단계 상한·효과는 [permanent_progression.json](../data/permanent_progression.json)을 단일 원본으로 한다.
- production의 새 프로필·전체 초기화와 스키마 1·2에서 마이그레이션한 프로필에는 다이아몬드 100개를 지급한다. development의 새 프로필·전체 초기화는 10,000,000개로 시작한다. 10웨이브 단위 최고 기록을 처음 달성할 때 50개씩(10~100), 보스 b10~b90 처치마다 20개, 승리 시 추가 100개를 판 종료 보상으로 지급한다. 보스·승리 보상은 해당 run 종료 거래에 묶고 같은 run의 재저장으로 중복 지급하지 않는다. 개발 판은 다이아몬드나 최고 기록을 보상하지 않는다. 이 가격·보상은 로컬 플레이용 튜닝값이다.
- 특수몬스터는 무료로 부르는 보상형 **적**이다. 10·30·60웨이브 완료, 즉 11·31·61 진입 시 해금한다. 보스 처치는 추가 조건이 아니다.
- 종류별 쿨타임 300게임초는 소환 성공 때 시작한다. 같은 종류도 시간이 지나면 동시에 존재할 수 있다. 아군 칸을 사용하지 않고 처치 보상을 준다. 소환 후 60게임초가 지나면 해당 특수몬스터만 보상 없이 사라지며 패배하지 않는다. 앱 종료 중에는 쿨타임이 진행하지 않는다.

## 승패와 기록

- 목숨 수치·표시·목숨 감소 진동은 없다. 살아 있는 보스·마왕이 60게임초의 기한을 맞으면 패배하며, 특수몬스터의 기한 만료는 패배 원인이 아니다.
- 모든 종류를 합친 전장 적 수가 한도(현재 50)를 초과하는 **51번째 생성 순간** 즉시 패배한다. 같은 틱 공격으로 구제하지 않고 후속 생성·거래를 차단한다. 한도 값은 튜닝 데이터에서 관리한다.
- 유일한 승리는 마왕 처치다. 일반적인 동시 사건 순서는 피해·사망 확정 → 마왕 처치 승리 → 특수몬스터 기한 만료 제거 → 살아 있는 보스 기한 패배 → 이동·웨이브 전환이다. 앞서 생성 시 확정된 개체 수 초과 패배를 이 순서로 되돌리지 않는다.
- 승리 시 살아 있는 특수몬스터는 정상 처치 보상과 이력을 한 번 반영한다. 나머지 적의 일괄 정리는 처치 보상을 주지 않는다. 종료 후 이동·생성·차감·입력 거래는 중단한다.
- 최고 도달 웨이브와 클리어 여부를 분리한다. 100웨이브 패배는 최고 100일 수 있지만 클리어가 아니다. 개발용 웨이브 점프 판은 최고 기록에 반영하지 않는다.
- 영구 성장이 없는 첫 도전의 최종 클리어는 사실상 불가능에 가까운 난도를 목표로 하며, 다이아몬드 영구 성장으로 클리어에 접근하도록 설계한다. 유료 구매 없이 획득한 다이아몬드의 성장 경로도 비교한다. 1·2성 강화와 2·3성의 군중 제어·디버프·보조 능력이 초중반에 실질적인 가치를 가져야 하며, 고성급으로만 채우는 구성이 항상 최선이어서는 안 된다. 기존 용병 디자인 변경은 최후의 수단이며 5성 설계는 미정이다. 자동 봇 결과를 사람의 첫 클리어율로 간주하지 않는다.

## UI·음향·진동

- 용병 선택 시 이름·공격 정보만 표시하며 판매·합성 버튼은 제공하지 않는다. 모든 용병 자세·그림자를 그린 뒤 성급 별표를 그려 서로 가리지 않게 한다.
- 다이아몬드 잔액·가격·보상·안내·부족 알림은 공통 보석 아이콘으로 표시한다. 메인 화면 하단의 잔액은 `아이콘 × 수량` 형식이며, 접근성 이름에는 각 언어의 재화 명칭을 보존한다.
- 골드 표시에는 공통 동전 아이콘과 숫자를 사용하며 특수문자로 대체하지 않는다. 버튼 텍스트와 아이콘 묶음은 중앙 정렬하고, 비용 표시는 글줄 높이에 맞춰 수직 중앙을 유지한다.
- 좌상단에 웨이브, 다음 웨이브/배치 준비 시간을 세로로 표시하고 그 아래에는 살아 있는 보스가 있을 때만 가장 가까운 처치 기한을 표시한다. 최상단 도구는 오른쪽부터 설정·도감·조합법이다. 조합법은 책 아이콘과 이름으로 강조하며, 메인 메뉴 이동은 설정에서 제공한다. 전장 적 수는 조합법 버튼 바로 아래의 202×54 패널에 24px 글자로, 골드는 도구 아래 오른쪽에 표시한다. 배속·정지/재개는 골드 아래에 둔다. 특수몬스터의 아이콘과 남은 시간은 우측 하단에 종류별로 표시한다. 배속은 현재 값 하나만 표시하고 설정과 분리한다.
- 아래 중앙 소환과 맨 아래 왼쪽부터 강화·도박·특수몬스터의 기존 위치를 유지한다. 불필요한 상시 가이드·긴 슬로건·소환 카드바는 추가하지 않는다. 공통 안내는 메뉴·전투·팝업 여부와 관계없이 화면 맨 위 `y=8`의 반투명 영역에 표시하며 마우스·터치 입력을 통과시킨다.
- 메뉴는 배경 위에 패널 없는 표시 제목과 새 게임·이어하기·도감·설정 버튼, 간결한 저작권/버전 푸터로 구성한다. 제목은 영문 세리프 글꼴을 별도로 사용하고 일반 UI의 한국어·기호 가독성을 유지한다. 유효 스냅샷이 없으면 이어하기를 비활성화한다.
- 메뉴에는 로컬 다이아몬드 잔액을 표시하며 메뉴의 영구 강화 창에서만 업그레이드를 구매한다. 구입 효과는 다음 새 전투부터 적용되고, 이어하기는 저장된 스냅샷의 단계를 유지한다.
- 일반 하단 창은 소환 버튼 위에 겹쳐 열고 전장을 축소하지 않는다. 창은 한 번에 하나이며, 가린 영역에 전장 입력을 통과시키지 않는다. 조합법·Records는 지정한 세로형 팝업 영역을 사용한다.
- 설정·조합법·도감·전투 강화 창을 열어도 전투는 계속된다. 수동 정지 상태에서는 모든 전투 진행과 게임 입력을 막으며, 성장 구매는 메뉴에서만 가능하다.
- 패널 텍스트는 가용 폭에 맞춰 줄바꿈하며, 조합·도감 목록 행은 내용 높이에 맞게 늘어난다. 스크롤 목록은 버튼을 누른 상태에서도 세로 이동이 드래그 임계값(현재 논리 좌표 20px)을 넘으면 스크롤로 전환하며 그 버튼의 클릭은 취소한다. 임계값 이하의 짧은 터치는 같은 버튼 안에서 정상적으로 뗄 때만 실행한다. 본문에서 시작해 다른 버튼 위를 지나거나 끝나는 드래그와 취소 입력은 버튼을 실행하지 않는다. 터치 환경의 임계값·관성·버튼 취소는 Godot `ScrollContainer`의 기본 기능을 사용하고 일반 마우스의 본문 드래그만 보완한다.
- 조합법은 결과 용병별로 초상·추적 버튼을 한 번만 표시하고, 각 용병의 유일한 조합식을 재료 수량·조합 버튼과 함께 표시한다. 현재 재료가 갖춰진 결과와 조합식을 먼저 표시한다. 기준 용병·무료 비용·결과 칸 안내는 표시하지 않는다. 용병의 공격 분류와 특수 능력은 조합법·도감에서 공통으로 표시한다. 표시용 거리 분류는 사거리 2.5 이하가 근접, 그 초과가 원거리이며, 피해 반경이 있으면 범위·없으면 단일이다. 공격력이 있으면 공격이며 아군 공격력 증가가 있으면 지원을 함께 표시한다. 둔화·기절과 아군 강화 수치는 실제 정의를 사용한다. 이 분류는 전투 판정을 변경하지 않는다.
- 별도 전투 가이드는 제공하지 않는다.
- 기본 언어는 영어이며 설정 맨 위 드롭다운에서 영어·한국어·간체 중국어·일본어를 선택한다. 언어는 기기에 저장하고 화면에 즉시 반영하며 진행 상태·정의 ID는 바꾸지 않는다.
- 적 기록의 이동 속도는 `28칸 / 한 바퀴 이동 시간`을 소수 둘째 자리의 `칸/초`로 표시한다. 배속·둔화가 적용되지 않은 게임초 기준 기본 속도이며 실제 전투 판정은 변경하지 않는다.
- 용병·적 도감의 표시 명칭은 한국어 `기록`, 영어 `Records`다. 현재 웨이브는 `웨이브: 1/100` 형식으로 표시한다.
- 조합법·Records 팝업은 720×1280 기준 `(35,128)` 위치의 `650×1024` 패널이며 좌우 여백은 35px, 상하는 128px다. 초상은 투명 여백을 실행 중 잘라 160×180 슬롯에 맞춘다.
- 조합법과 Records의 용병 목록은 같은 성급 필터(전체, 1~4성)와 거리(전체→근접→원거리), 대상(전체→단일→범위), 행동(전체→공격→지원) 순환 필터를 쓴다. 필터 조건은 AND로 결합한다. 표시 분류와 같은 기준을 사용한다. 공격은 `damage > 0`, 지원은 `buff > 0` 또는 `damage <= 0`이며 공격과 지원에 모두 해당하면 두 필터 모두에 남는다. 현재는 공격력 증가 버프가 있는 6종이 양쪽에 해당하고, 군중제어는 별도 특수 능력으로 표시한다.
- 도감은 전체 정의·조합을 열람할 수 있고 발견 여부를 따로 누적한다. `열람 가능`과 적의 `웨이브에 따라 체력 증가` 안내는 표시하지 않는다. 용병 영입과 적 등장으로 발견하며, 미발견 때문에 조합/도박을 막거나 영구 소유·수집 보상을 추가하지 않는다.
- 레시피 추적은 개수 제한 없이 현재 전투의 메모리에만 보관한다. 대상을 켜면 모든 하위 조합과 1성 재료까지 재귀적으로 추가하되 공유 재료는 중복하지 않고 기존 추적 순서를 보존한다. 조합식이 없는 1성은 준비 버튼을 만들지 않는다. 해제는 선택한 대상만 적용하며 다른 추적은 유지한다. 조합·팝업·언어 변경 중에는 유지하고 메뉴 복귀·새 전투·이어하기·앱 재시작에는 초기화한다. 프로필과 전투 스냅샷에는 저장하지 않는다. 준비된 추적 레시피는 화면 오른쪽에 최대 5개까지 표시하며 결과 성급 내림차순, 같은 성급은 추적 순서를 따른다. 추적을 해제했다 다시 켜면 순서 끝으로 이동한다. 조합을 누르면 현재 재료를 새로 검사하고, 선택 기준 용병 없이 조합을 실행한다. 팝업이 열리면 준비 버튼을 숨긴다.
- 전투 배경음악은 **안개의 파수**(`mist_guard`), UI는 일반 조작에 `tap`, 성공 확인에 `chime`을 사용한다. 클릭 하나에서 확인음과 탭음을 중복 재생하지 않는다.
- 배경음악과 효과음 음량·음소거는 별도 저장한다. 슬라이더 왼쪽 사운드 아이콘으로 끄고 다시 켜며 기존 음량을 보존한다. 음량을 직접 조절하면 음소거를 해제하고, 0에서는 완전히 끈다. 0인 채 아이콘으로 켜면 해당 채널의 기본 음량으로 복구한다. 반복 청취에 부담 없는 음량과 질감을 유지하고 공격음은 실제 공격 이벤트에 연결한다. 믹싱·용량·재사용 기준은 [리소스 안내](RESOURCE_GUIDE.md)를 따른다.
- 진동은 기본 꺼짐이다. 켜짐 전환 100ms와 클리어 320ms만 요청하며 강도는 0.45로 고정한다. 패배·설정 복원·결과창 재개방에는 추가 진동이 없다. 백그라운드에서는 소리·진동을 억제한다.

## 저장·복원

- 설정·도감·처치 이력·최고 기록·로컬 경제는 프로필에, 진행 중 상태는 별도 스냅샷에 저장한다. 새 판에 판 내 골드·용병·강화를 상속하지 않으며 영구 단계는 새 판을 만들 때만 복사한다.
- 스냅샷은 버전·run ID·시간·다음 생성·개체 ID·HP/위치·쿨타임·군중제어·RNG 상태 등 이어하기에 필요한 상태를 보존한다. 노드·이미지·표시 이벤트는 저장하지 않는다. RNG seed/state는 JSON 정밀도 손실을 피하도록 문자열로 쓴다.
- 실제 시간 10초 주기, 경제/배치 변경 후 0.3초 합치기, 웨이브 경계, 백그라운드·메인 복귀·정상 종료에 저장한다. 매 프레임 쓰거나 강제 종료 직전 미저장 프레임까지 복구한다고 보장하지 않는다.
- 프로필 스키마 6은 빌드 스테이지 `stage`와 로컬 `economy`(지갑·영구 단계·원장)와 정상 전투의 보스 처치 증거 `cleared_boss_waves`를 저장한다. `preferences.recipe_tracking`은 저장하지 않는다. 스키마 1·2는 기존과 같이 초기 경제를 추가하며, 스키마 3·4의 경제와 구매 이력은 보존한다. 구버전 `speed`는 신규 구매를 중단하고 새 `battle_speed`의 원시 단계는 0으로 추가한다. 기존 유료 배속은 유효 단계 계산으로 승계하며 과거 거래를 재작성하거나 가상 구매를 추가하지 않는다. 보스 처치는 정상 종료 원장과 연결된 개별 run 처치 기록 또는 검증된 정상 진행 스냅샷으로만 이전하며 전체 처치수·최고 웨이브·개발 판은 근거로 삼지 않는다. 스키마 3 이상 경제는 잔액·단계·원장 합계를 검증하고 미래 스키마는 읽기 전용으로 연다.
- 실행 스냅샷 스키마 6은 빌드 스테이지 `stage`, 유료 소환 횟수 `paid_summons`, 남은 5초 준비 시간, 사용자 수동 정지, 새 전투에 고정된 영구 단계와 전투 상태를 보존한다. 스키마 1은 준비 시간 0초·영구 효과 없음·자동 정지 없음으로 읽는다. 스키마 2는 저장된 구매 단계와 사용자 정지를 보존한다. 소환 횟수가 없는 스키마 1·2는 업데이트 이후 유료 소환부터 횟수를 세며 기존 골드·용병·RNG는 보존한다. 스키마 3 이상은 소환 횟수 누락·음수·소수·생성 개체 수 초과를 거부한다. 스키마 4부터 목숨 대신 보스·특수몬스터의 절대 게임시간 `deadline`을 저장한다. 재시작으로 기한을 늘리지 않으며 일반 적에는 기한을 허용하지 않는다. 스키마 1~3의 목숨은 기존 범위로 검증한 뒤 버리고, 보스는 등장 웨이브로 마감을 계산한다. 이미 마감이 지난 구버전 보스는 기존 시간·웨이브를 되감지 않고 즉시 패배로 이전한다. 생성 시각이 없던 기존 특수몬스터에만 첫 이전 시점부터 60초를 부여한다. 프로필 보상은 run 결과와 경제 변경을 한 번의 프로필 기록으로 원자 반영하며, 원장 ID로 같은 최고 웨이브·run 보상을 중복 지급하지 않는다. 구버전의 무료 ×3·×5는 유효한 저장으로 읽은 뒤 새 구매 권한이 없으면 ×2로 낮추고, 기존 유료 배속은 유지한다. 기한 이전은 스키마 1~3에만 적용하며 스키마 4의 기한은 그대로 보존한다. 이어하기 중 구매 단계 변경은 불가능하다.
- 임시 파일을 같은 경로에서 교체하고 정상 이전 파일은 백업한다. 손상되었거나 지원하지 않는 과거 형식의 파일은 고유 `.corrupt-*`로 보존하고 부적절한 이어하기를 거부한다.
- 프로필의 종료 ID와 처치 반영 상한을 먼저 확정해 이전 스냅샷으로 보상이 중복되지 않게 한다. 결과가 안전하게 저장된 뒤 진행 중 스냅샷을 제거한다.
- 새 게임이 기존 판을 덮을 때 확인한다. 이어하기는 저장된 수동 정지 여부를 따르며 앱이 꺼진 동안 진행·골드·쿨타임 보상을 주지 않는다.
- 스냅샷의 `path_length`는 현재 28이다. 값이 없거나 26인 이전 저장은 적 진행도에 `28/26`을 곱해 주회 비율을 보존한다. 다른 경로 길이는 거부하며, 이동 시간·개체 ID·HP·RNG를 바꾸지 않는다.
- 지원하는 0.2 저장은 개체 ID·HP·RNG를 유지한다. 0.2의 한도 초과 활성 판은 상태를 보존한 패배로 옮기며, 현 버전의 한도 초과 활성 판과 알 수 없는 버전은 거부한다.
- Web의 로컬 파일 쓰기와 IndexedDB 영속화는 비동기다. 테스트는 영속화 완료 후 재시작을 검증한다. 즉시 탭 종료 보장과 관련한 남은 작업은 [REMAINING](REMAINING.md)에서 관리한다.

## 빌드 스테이지와 전체 초기화

- production과 development는 내보내기 전 별도 프로젝트 사본으로 만든다. development 전용 코드 구간은 production에서 물리적으로 제거하고, 스테이지 상수·초기 다이아몬드·저장 경로를 해당 빌드의 값으로 생성한다. 런타임 메뉴·환경 변수·URL·저장 데이터로 스테이지를 선택하지 않는다.
- production은 기존 `user://` 저장을 이어 쓰고 development는 `user://development`를 사용한다. Web에서는 이 경로를 별도의 IndexedDB로 마운트해 두 스테이지의 동시 동기화가 충돌하지 않게 한다. 프로필·전투 스키마 6의 `stage`가 실행 빌드와 다르면 읽지 않는다. 스테이지가 없던 스키마 1~5는 기존 production 기록으로만 이전한다. 개발 빌드의 메인 화면에는 DEVELOPMENT 표기를 더한다.
- 설정의 게임 초기화는 현재 스테이지의 다이아몬드·영구 강화·기록·발견 정보·설정·진행 중 전투와 그 백업을 모두 지운다. 되돌릴 수 없음을 확인하는 별도 창에서 사용자가 확정해야 하며 취소는 데이터를 바꾸지 않는다. 다른 스테이지는 지우지 않는다. 중단된 초기화는 기록한 삭제 의도를 따라 다음 시작 때 마저 처리하고, 예전 전투를 자동 저장하거나 백업에서 되살리지 않는다.
- 위 격리는 정상 실행의 스테이지 전환·데이터 혼합을 막는 계약이다. 동일 출처의 Web 저장소와 사용자 소유 클라이언트 전체를 공격자가 수정하는 상황의 신뢰 경계는 아니다. 유료 재화에는 별도의 서버 권한 검증이 필요하다.
