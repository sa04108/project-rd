# 리소스 용량 권장 기준

## 원칙

- 기존 리소스와 새 리소스 모두 **파일당 약 1 MB 이하를 권장**한다. 도구의 표시 기준은 1,000,000바이트이며, 강제 제한이나 빌드 실패 조건이 아니다.
- 크기나 고화질 자체보다 게임에서 식별 가능한 표현, 정확한 투명도, 기존 경로·임포터 호환성을 우선한다. 이를 위해 필요하면 1 MB를 넘겨도 된다.
- PNG만 가능한 것은 아니다. WebP도 투명도를 지원한다. 다만 현재 계열 임포터는 RGBA PNG 색상 유형 6을 검사하고 여러 경로가 `.png`로 고정되어 있어, 확장자 일괄 변경은 하지 않는다.
- 작은 런타임 아틀라스는 디코딩한 RGBA 픽셀을 그대로 유지하는 무손실 압축을 사용한다. 원본 제작 시트의 RGB 손실 압축은 검토 후 별도로 선택할 수 있다.
- **알파를 양자화하거나, 용량만을 이유로 자동으로 해상도를 줄이지 않는다.**
- 파일 재인코딩 뒤에는 원본 바이트가 달라진다. 픽셀이 같은 무손실 압축도 새 SHA-256을 기록하며, 이전 생성 원본과 압축 파생본을 구별한다. 이전 Git 커밋이나 파일 이력을 삭제하지 않는다.

## 도구

`tools/art/optimize_images.py`는 Pillow를 사용하는 독립 CLI다. 기본 실행은 파일을 읽어 JSON 비교 결과를 표준 출력으로 내보낼 뿐, 리소스·백업·미리보기 파일을 쓰지 않는다.

명시적으로 지정한 저장소 내 8비트 RGB/RGBA PNG만 처리한다. 디렉터리를 자동 순회하지 않으며, 파일과 상위 디렉터리의 심볼릭 링크는 건너뛴다. 팔레트 PNG, 16비트 PNG, APNG는 별도 검토가 필요해 거부한다.

| 방식 | 픽셀 계약 | 적용 조건 |
| --- | --- | --- |
| `png-lossless` | RGBA 픽셀·알파·크기 완전 동일 | 기본값. RGB 입력은 RGB, RGBA 입력은 유형 6 유지 |
| `png-clean-alpha0` | A=0인 픽셀의 RGB만 0으로 정리. 나머지 RGB와 모든 알파 동일 | 제작 시트/배경 역할과 명시적 허용 필요. 필터링 경계 검토 |
| `png-rgb` | RGB만 최대 256색으로 줄인 뒤 원본 알파를 복원. 출력은 RGBA PNG 유형 6 | 제작 시트/배경 역할, 손실 허용, 품질 하한 통과 필요 |
| `webp-lossless` | 디코딩 RGBA 완전 동일 여부 검사 | 비교·외부 미리보기 내보내기만 지원 |
| `webp-lossy` | RGB 손실 허용 후보. 모든 알파·크기는 동일해야 함 | 비교·외부 미리보기 내보내기만 지원 |

WebP는 경로·임포터·색 관리·플랫폼 아이콘 요건을 별도 검토하고 채택해야 한다. 도구는 PNG를 WebP로 덮어쓰거나 참조 경로를 고치지 않는다. PNG 색상 프로필·텍스트 등 부가 청크는 보존한다. WebP에는 ICC/EXIF/XMP가 있으면 복사하지만 PNG의 gamma/chromaticity/resolution 청크를 자동 변환하지 않으므로, 픽셀 수치 비교만으로 색 관리까지 같다고 판단하지 않는다.

### 먼저 비교

```bash
python tools/art/optimize_images.py \
  docs/art-generation/u01/attack.source.png \
  assets/art/orthographic/battle-map.png \
  assets/art/backgrounds/app-icon.png
```

다섯 방식의 결과를 직접 보려면 저장소 밖 출력 위치를 명시한다. 이 실행도 원본 리소스는 바꾸지 않는다. 미리보기와 영수증은 요청한 출력에만 새로 쓴다.

```bash
OUT="$(dirname "$PWD")/image-size-review"
python tools/art/optimize_images.py \
  docs/art-generation/u01/attack.source.png \
  assets/art/orthographic/battle-map.png \
  assets/art/backgrounds/app-icon.png \
  --method compare --role source \
  --preview-dir "$OUT/previews" --receipt "$OUT/comparison.json"
```

`--role source`는 비교 대상의 손실 후보를 평가하기 위한 명시적 역할 선택이다. 런타임 아틀라스에 이 역할을 사용하지 않는다. `compare` 결과의 품질 통과와 실제 적용 가능 여부는 별도 필드이며, opt-in이 없으면 해당 후보는 적용할 수 없다.

### 검토 후 적용

파일을 바꾸려면 `--apply`와 **저장소 밖 `--backup-dir`**를 모두 지정해야 한다. 아래 명령은 예시이며, 이 문서를 작성한 검증에서는 실제 저장소 리소스에 적용하지 않았다.

```bash
BACKUP="$(dirname "$PWD")/resource-original-backups"
python tools/art/optimize_images.py \
  assets/art/identities/u01/atlas.png \
  --apply --backup-dir "$BACKUP"
```

제작 시트에서 완전히 투명한 영역의 RGB를 정리하는 경우:

```bash
python tools/art/optimize_images.py \
  docs/art-generation/u01/attack.source.png \
  --method png-clean-alpha0 --role source \
  --allow-transparent-rgb-cleanup \
  --apply --backup-dir "$BACKUP"
```

일반적인 직접 알파 합성에서는 A=0의 RGB가 보이지 않는다. 하지만 필터링 방식에 따라 경계 샘플링 결과가 달라질 수 있으므로 이를 “RGBA 픽셀 완전 동일”이라고 기록하지 않는다. 런타임 역할에서는 이 방식을 적용할 수 없다.

제작 시트의 RGB를 줄이려면 `--method png-rgb --role source --allow-lossy`를 별도로 선택한다. 원본과 미리보기를 검토하고 품질 하한을 통과한 경우에만 `--apply`를 붙인다. 필요하다면 검토 후 `--min-psnr`를 조정할 수 있지만, 1 MB 이하를 맞추려고 자동으로 낮추지는 않는다.

### 검증·복구 계약

- 바꾸기 직전 원본 바이트를 다시 확인한다. 평가 이후 파일이 바뀌면 교체하지 않는다.
- 실행마다 고유한 백업 디렉터리를 만들고 원본 바이트를 보존한다. 백업 SHA-256과 사전 영수증 기록이 성공한 뒤 같은 디렉터리 내 임시 파일을 원자적으로 교체한다.
- 각 파일의 이전/이후 바이트 수, SHA-256, 크기, 모드, RGBA 해시, 알파 해시, 알파 분포, 오차 지표, 백업 위치를 기록한다. 백업과 영수증은 저장소 안에 둘 수 없다.
- 더 작은 결과만 채택한다. 작아지지 않거나 품질/호환성 검사에 실패하면 원본을 유지한다. 1 MB 초과 자체는 실패가 아니다.
- 기본 손실 품질 하한은 **보이는 픽셀 RGB PSNR 38 dB 이상**, 검정·흰색 배경 합성 후 **채널당 최대 오차 48/255 이하**다. 완전히 투명한 영역을 PSNR 분모에서 제외해 넓은 빈 공간으로 오차가 숨겨지지 않게 한다. 알파와 크기는 항상 정확히 같아야 한다.
- 이 지표는 육안 검토와 게임 렌더링 검증을 대체하지 않는다. `--min-psnr`는 30~60, `--max-error`는 1~64 범위에서 명시적으로 조정할 수 있다.
- 배치 전체가 하나의 트랜잭션은 아니다. 파일별 상태와 영수증을 확인한다. 실패한 파일이 있어도 먼저 적용된 파일은 보존되며 각각 복구할 수 있다.
- 도구는 아트 메타데이터, `source_sha256`, `atlas_sha256`, review/pipeline receipt 등을 자동 수정하지 않는다. 채택한 파일에 해당하는 기존 영수증을 별도 갱신하고 생성 원본 해시·압축 파생본 해시·변환 설정을 함께 남긴다. 무손실 재인코딩도 “생성 원본 바이트 그대로”라고 표시하면 안 된다.

## 대표 파일 비교 결과

2026-10-03, Pillow 12.3.0, WebP quality 85/method 6, RGB 팔레트 256색. 원본과 모든 후보의 크기는 그대로이며 알파 해시가 동일했다. 저장소 리소스는 변경하지 않고 저장소 밖 격리 디렉터리에 후보를 만들었다.

| 방식 | 제작 시트 `u01/attack.source.png` | 전장 `battle-map.png` | `app-icon.png` |
| --- | ---: | ---: | ---: |
| 원본 | 1,908,363 B | 3,252,302 B | 3,152,770 B |
| PNG 픽셀 완전 무손실 | 1,802,100 B | 3,250,827 B | 3,150,860 B |
| PNG + A=0 RGB 정리 | 1,044,953 B | 3,250,827 B | 3,150,860 B |
| RGBA PNG + RGB 256색 | 939,705 B | 3,089,750 B | 2,683,812 B |
| WebP 완전 무손실 | 1,324,268 B | 2,467,564 B | 2,585,278 B |
| WebP 손실 q85 | 237,284 B | 501,174 B | 475,316 B |

손실 후보 지표:

| 후보 | 제작 시트 PSNR / 최대 합성 오차 | 전장 | 아이콘 |
| --- | --- | --- | --- |
| RGB 256색 PNG | 35.0219 dB / 45 | 33.9962 dB / 106 | 31.2915 dB / 105 |
| WebP q85 | 31.5600 dB / 78 | 33.4159 dB / 89 | 30.2923 dB / 121 |

이 여섯 손실 후보는 기본 보수적 하한을 통과하지 않았다. 시트의 256색 PNG는 별도 육안 검토 후 35 dB 하한으로 선택하면 통과하지만, 약 1.045 MB의 무손실 시각 결과를 유지하는 선택도 충분히 권장 기준에 맞는다. 배경/아이콘에 같은 256색 처리를 일괄 적용할 근거는 없다.

직접 확인한 내용:

- 세 원본과 여섯 방식의 256×256 원본 배율 부분 확대, 알파 합성한 전체 제작 시트를 실제 이미지로 확인했다.
- 픽셀 완전 무손실 방식과 A=0 RGB 정리는 직접 합성에서 같은 표현을 유지했다. 시트의 RGB 256색 후보에는 작은 색 단순화, WebP q85에는 경계 색 변화와 일부 디테일 완화가 보였다.
- `u01/attack` 원본과 A=0 RGB 정리본을 각각 별도 격리 디렉터리에서 기존 `import_identity.py`로 패킹했다. 두 768×512 런타임 아틀라스의 **PNG 바이트까지 동일**했다. 이 결과는 해당 시트·현재 패커에 대한 검사이며 모든 리소스/필터의 보장을 뜻하지 않는다.
- 이 도구 변경만으로 Godot 재임포트나 실제 게임 전체 렌더링 검증을 수행한 것은 아니다. 실제 리소스를 채택한 뒤 해당 검증을 별도로 진행한다.
