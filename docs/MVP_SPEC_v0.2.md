# project-rd — MVP 개발 명세 v0.2

**Godot / 오프라인 / 세로 모바일 / 내부 시스템·재미 검증**

이 문서는 v0.1과 이후 사용자 수정을 통합한다. 본문만으로 구현을 시작할 수 있도록 규칙과 초기 해석을 완결해 두었다. 게임 구현이나 QA 완료를 주장하는 문서는 아니다.

## 0. 문서의 권위와 의사결정

| 표시 | 의미 | 개발 AI의 처리 |
|---|---|---|
| **F — 확정** | 사용자가 명시하거나 승인한 요구 | 임의 변경 금지 |
| **I — 구현 해석** | 동시에 주어진 요구를 좌표·시간·저장 규칙으로 구체화 | 의도를 유지해야 하며 다른 구현은 동등성 검증 필요 |
| **D — 작업 기본안** | 아직 사용자 확정이 아닌 빈틈의 초기 결정 | 사용자의 답을 기다리지 않고 적용 가능. 변경 시 근거·영향을 기록 |
| **T — 튜닝** | 미지정 가격·확률·공격·강화·CC 수치 등 | 개발 AI가 정하고 플레이 검증으로 개선 |

권위는 최신 사용자 요구 → F → I → D → 콘텐츠 초안 → 이미지 순이다. 과거 이미지의 문자·확률·경로·배치는 명세가 아니다. `data/game_rules.json`에도 이 구분을 유지한다. 사용자 고정값은 밸런스 실험 대상으로 취급하지 않는다.

**최신 변경:** 방어력 표기를 제거한다. 목숨은 좌상단에 `♥ × 현재 목숨`, 시작 시 `♥ × 20`. 배속은 버튼 하나로 `×1 → ×2 → ×3 → ×5 → ×1` 순환한다. ×4나 여러 배속 버튼은 없다.

## 1. 목표·범위·미포함 [F]

프로젝트명은 `project-rd`, 출시 제목은 미정이다. 향후 Play Store 출시를 지향하되 이번 산출물은 외부 출시판이 아닌 **내부 핵심 재미와 작동 검증용 MVP**다. 사용자는 독특함보다 익숙하고 전형적인 판타지와 신파적 영웅 서사를 선호한다.

세계관은 세계 각지 용병이 모이는 용병 길드, 외형은 클래식 하이 판타지다. 검·활·지팡이·도복·복면·갑옷·성직 로브로 직업을 즉시 구분한다. 과도한 픽셀아트가 아닌 약한 도트 느낌의 2D 스타일이다. 레퍼런스에서 색감·캐릭터 비율을 참고하되 복잡한 장식·문구를 전부 복제하지 않는다.

Godot을 사용한다. 최신 사용자 지시에 따라 고정 정투영(orthographic), 세로 화면이며 카메라 이동·회전은 없다. 화면의 6×6칸은 모두 가로·세로가 같은 정사각형이며 건물·기물·배경도 소실점이나 원근 축소가 없어야 한다. 2D 조립식 캐릭터·공통 본·동작·부품 공유 방식과 공통 6계열+용 1계열을 채택한다.

핵심 루프는 **골드 획득 → 무작위 1성 소환 → 레시피 조합 → 칸 재배치 → 사거리·화력·CC 운용 → 100웨이브 마왕 처치**다.

5성, 영구 재화·용병·강화, 서버, 계정, 멀티플레이, 랭킹 서버, 광고, 결제, 에너지, 출석 보상은 범위 밖이다. 모험형 필드 이동이나 아군 탱킹·피격 전투를 추가하지 않는다. 낮은 비용의 효과·사운드·입력 피드백은 핵심 루프를 개선하는 범위에서 제작한다.

## 2. 전장·좌표·외곽 경로

### F-BOARD: 배치와 경로

아군 영역은 **6열 × 6행 = 36칸**, 한 용병은 한 칸을 점유한다. 중앙은 정투영 풀바닥이며 높이에 따른 격자 변형은 없다. 중앙과 외곽 사이에 벽은 없으며, 용병은 외곽 통로에 들어갈 수 없다. 무기와 오라는 칸을 약간 넘을 수 있지만 몸의 기준점과 논리 점유는 한 칸이다.

외곽을 포함한 전체 공간은 **7×7단위**다. 적은 좌상단에서 시작해 **왼쪽 아래 ↓ → 아래쪽 오른쪽 → → 오른쪽 위 ↑ → 위쪽 왼쪽 ←** 순으로 한 바퀴를 돌아 탈출한다. 경로를 무한 순환시키지 않는다. 입구와 출구는 한 바퀴를 끝내는 좌상단 부근에서 시각적으로 구분하되 길을 단축하지 않는다.

### I-COORD: 거리 규격

- 지면 좌표 x는 오른쪽, y는 아래쪽 증가. 아군 영역은 [0,6]×[0,6].
- 1부터 세는 행 r, 열 c의 칸 중심은 `(c-0.5, r-0.5)`.
- 전체 범위는 [-0.5,6.5]×[-0.5,6.5], 외곽 통로 폭은 각 변 0.5.
- 적 경로 중심선의 초기 점은 `(-0.25,-0.25)`이고 다음 점은 `(-0.25,6.25) → (6.25,6.25) → (6.25,-0.25) → (-0.25,-0.25)`.
- 직선 사각 중심선 길이는 26단위다. 적은 경로 진행 거리와 `spawn_wave`를 가진다. 끝에 도달하면 한 번만 탈출 처리한다. 마지막 구간에서 좌표가 시작점과 같다는 이유로 진행도를 0으로 되돌리지 않는다.
- 7×7개의 같은 크기 타일을 뜻하지 않는다. 1칸짜리 길을 양쪽에 덧붙여 8×8로 바꾸지 않는다.
- 최종 카메라 투영과 논리 지면 좌표는 분리한다. 최신 사용자 지시에 따라 두 축에 동일한 배율을 적용하며 원형 사거리는 화면에서도 원형으로 표시한다.

검증 예: 3행3열 중심 `(2.5,2.5)`와 오른쪽 통로 `(6.25,2.5)`의 거리는 3.75. 사거리 3.0은 미달이고 3.8은 도달한다. 화면 그림이나 무기 끝을 거리 계산에 사용하지 않는다.

## 3. 배치·조작·소환

### F-INPUT: 상시 재배치

용병을 탭한 뒤 목적지 칸을 탭하거나, 드래그해서 이동한다. 전투 중에도 가능하다. 용병은 자동으로 적을 추격하지 않는다. 선택하면 원형 사거리를 표시한다. 사거리는 소수점 한 자리의 데이터와 표시를 지원한다.

### F-SUMMON: 소환·빈칸·골드

일반 소환은 골드를 사용해 무작위 1성 용병 한 명을 만든다. 빈칸 탐색은 **왼쪽 열 위→아래, 다음 열 위→아래**다. 매번 첫 빈칸부터 찾으며 기존 용병을 밀거나 정렬하지 않는다. 최초 6회는 첫 열, 7회는 두 번째 열 맨 위다. 중간 빈칸이 생기면 그 칸부터 채운다.

시작 골드는 1성 3명을 소환할 수 있는 양이다. 초기 용병을 자동 지급하는 규칙은 없다. 골드·용병·업그레이드는 이번 판 한정이다. 새 판은 초기 상태로 시작한다. 소환 가격이 가변이면 첫 세 번의 가격 합으로 초기 골드를 정의한다. **D 초기안은 판 내 기본 소환 가격 고정**이다.

36칸이 찼으면 일반 소환과 도박 시작을 막고 차감·추첨을 하지 않는다. 조합은 재료를 소비해 공간을 만들 수 있으므로 가능하다. 골드 부족·잘못된 타깃·기타 실패에도 자원이나 개체를 부분적으로 잃지 않는다. UI 비활성화 외에 로직에서도 검증한다.

### D-INPUT: 비어 있던 조작 기본안

점유된 칸으로 이동하면 두 용병의 칸을 교환한다. 드래그로 자동 조합하지 않는다. 논리 점유는 원자적으로 변경하고 짧은 이동 연출만 추가한다. 이동·교환으로 공격 타이머를 초기화하지 않는다. 화면 바깥·외곽 통로·가려진 UI 아래로 드래그하면 기존 칸을 유지한다. 같은 칸 이동은 무변경이다.

일시중지는 게임 시간 정지이고 UI를 종료하는 것이 아니다. **D:** 명시적 일시중지 중에도 UI와 합법적인 재배치·경제 조작은 사용할 수 있다. 설정창이나 배경 전환은 화면 접근을 막는다. 정지/재개로 타이머를 초기화하지 않는다.

## 4. 전투·사거리·CC

### F-COMBAT

적은 아군 용병을 공격할 수 없다. 아군은 배치 칸에서 사거리 내 적에게 공격한다. 중앙 경계에는 투사체·공격을 막는 벽 판정이 없다. 아군 체력 감소·사망·부활·탱킹 전투를 필요 기능으로 만들지 않는다. 사제는 회복할 아군을 찾는 대신 화력 지원 등의 역할을 사용한다.

둔화·기절 등 CC로 경로 진행을 늦출 수 있다. 이전 웨이브 적이 여러 다음 웨이브에 남는 것이 정상이다. 마왕도 CC로 저지할 수 있어야 한다. CC를 무효화하는 무조건적 마왕 면역이나 30초 강제 종료를 넣지 않는다.

방어력은 전투 HUD·강화·도감·용병 설명의 능력치 표기에서 제거한다. 적의 내부 피해 감소나 취약 효과를 쓰는 것은 별도 밸런스 설계이며, 이를 이유로 아군 방어력 업그레이드나 방어력 표기를 되살리지 않는다.

### D-COMBAT / T

초기 타깃은 사거리 안에서 경로 진행도가 가장 큰 적, 동률은 안정적인 개체 ID 순으로 한다. 범위 판정은 중심점의 지면 거리 `distance <= range`. 공격 자체의 대상·피해 판정과 시각 이펙트를 분리한다. 기본 공격은 자동 수행하고 수동 스킬 버튼은 추가하지 않는다.

CC 지속시간·둔화율·중첩 정책·적 체력·공격 주기·피해는 튜닝 데이터로 둔다. 초기 중첩안은 둔화는 가장 강한 효과 적용, 기절은 더 늦은 만료 시각 유지다. 동일한 CC 갱신과 무제한 영구 기절의 결과를 실제로 검증한다. 플레이로 오래 저지한 적을 정리한다는 이유로 자동 삭제하지 않는다.

사용자 미지정 밸런스는 개발 AI가 조정할 수 있다. 다만 효과 데이터에 없는 치유·방어·반격을 그림이나 직업명에서 추론해 추가하지 않는다.

## 5. 시간·웨이브

### F-WAVE

총 100웨이브, 10의 배수 웨이브에 보스가 나오며 100웨이브는 마왕이다. 1~99웨이브는 각각 **30게임초**이고 다음 웨이브와 사이에 대기시간이 없다. 일반 웨이브마다 적 **10마리**를 생성한다.

CC가 없고 처치되지 않았다는 기준에서 일반 웨이브의 마지막 적은 웨이브 시작 **27초**에 탈출하도록 생성 일정과 이동속도를 맞춘다. 다음 웨이브는 30초에 시작한다. 실제 전멸·탈출을 기다렸다가 3초를 더하는 로직이 아니다. 전멸했다고 앞당기거나 적이 남았다고 늦추지 않는다.

100웨이브는 종료 타이머가 없다. 마왕은 CC가 없으면 등장 후 **30초 안에** 경로를 완주한다. CC로 그 시간이 늘어나는 것은 의도한 플레이이며 생존 중이라는 이유로 시간제 패배를 처리하지 않는다.

### I-SCHEDULE / D-WAVE

일반 웨이브 초기 일정은 `t=0,1,…,9초`에 한 마리씩, 기본 경로 완주 18초다. 따라서 마지막 생성9초 + 이동18초 = 27초. 적 종류에 따라 기본 이동속도를 달리하려면 여전히 기준 마지막 탈출이27초가 되는 일정을 검증한다. MVP에서는 구간별 속도는 같게 두고 체력·외형부터 달리해도 된다.

**D:** 10~90 보스 웨이브는 보스 한 마리만, 시작0초 생성, 기본 완주27초. 보스가 생존해도 다음 웨이브로 넘어간다. 100웨이브는 마왕 한 마리, 시작0초 생성, 기본 완주30초. 이전 적·특수몬스터는 남는다.

시간 원점이1웨이브 시작0초일 때2웨이브는30초,10웨이브는270초,11웨이브는300초,100웨이브는2970초에 시작한다. 101웨이브는 없다. 개발 도구로 점프한 경우는 이 정상 플레이 시간과 분리해 표시한다.

생성 누적시간을 안정적으로 처리한다. 배속·프레임 저하 때문에 생성 이벤트를 건너뛰거나 두 번 발생시키지 않는다.

## 6. 목숨·승패·기록

### F-RESULT

시작 목숨은 **20**이다. 일반 적·보스·특수몬스터 한 마리가 탈출할 때 **목숨1** 감소,0이면 패배다. 마왕은 탈출하면 목숨이 남아도 즉시 패배한다. 모든 탈출의 기본 차감은 적용하되 마왕 탈출 원인을 별도로 기록한다.

**유일한 승리 조건은 100웨이브 마왕 처치**다. 즉시 승리 판정하며 살아 있는 특수몬스터도 함께 처치한다. 남아 있는 일반 적·보스가 승리를 지연시키지 않는다. 100웨이브 진입이나 경과시간만으로 승리하지 않는다.

패배 시 현재 도달한 웨이브를 기존 최고와 비교하여 최대값으로 저장한다. 완료 웨이브가 아니라 진입한 웨이브다. 100웨이브 패배는 최고100일 수 있지만 클리어는 아니다. 최고 도달 웨이브와 클리어 여부를 별도로 저장한다.

### D-RESULT: 경합·종료

한 시뮬레이션 틱에서는 피해와 사망 확정 → 마왕 사망 승리 → 살아 있는 적의 탈출 순으로 처리한다. 같은 틱의 마왕 처치와 다른 적 탈출이 겹치면 확정된 마왕 사망에 우선권을 준다. 사망 개체는 탈출 차감을 하지 않는다. 종료는 단 한 번만 발생하며 종료 이후 생성·이동·차감·재입력은 정지한다.

승리 시 특수몬스터는 정상 처치 보상·발견/처치 이력을 한 번 반영한다. 나머지 일반 적의 종료 정리는 정상 처치 보상을 주지 않는다. 최고 기록은 승리에도 갱신한다. 진행 중 스냅샷은 결과와 장기 기록이 안전하게 저장된 후 제거하여 재실행으로 보상을 중복 적용하지 않는다.

## 7. 조합

### F-RECIPE

2성 결과에는 **1성 용병 두 명**, 3성 결과에는 **2성 용병 두 명**이 필요하다. 두 재료는 같은 용병일 수도 다를 수도 있다. 재료 종류는 개별 레시피가 정한다. '같은 성급'은 아무 두 개체가 무조건 조합된다는 뜻도, 동일 용병만 허용한다는 뜻도 아니다.

4성은 특수 레시피다. 예를 들어3성3명 또는 지정된1·2·3성 혼합을 쓴다. 3성 두 명을 일괄4성으로 올리는 공통 규칙은 없다.5성은 없다. 적은 조합 대상이 아니다.

선택한 기준 재료 칸에 결과를 놓고 다른 재료 칸은 비운다. 유효한 작업만 원자적으로 실행한다. 같은 개체를 여러 재료로 중복 소비하지 않는다. 중간 실패로 재료만 없어지지 않는다.

### D-RECIPE

결과는 레시피에 지정한 고정 용병이다. MVP는 소속 태그 와일드카드보다 정확한 재료 ID·수량으로 구현한다. 조합법 창에서 재료·결과·부족 상태를 표시하고 수동 실행한다. 골드 조합 비용은 지정되지 않았으므로 초기안은 **무료 조합**이다. 추후 비용 도입은 단순 확률 수치 변경이 아닌 경제 동작 변경이므로 근거를 기록한다.

기준 용병을 선택한 상태면 그 개체를 사용할 수 있는 레시피에서 기준 칸을 유지한다. 기준이 없으면 열 우선 첫 재료 칸을 명확히 강조한 뒤 실행한다. 여러 동일 재료 후보는 열→행→개체ID 순으로 골라 결과를 재현할 수 있게 한다. 창 표시 후 재료가 달라졌으면 실행 시 재검증한다.

## 8. 골드·업그레이드·도박

### F-ECONOMY

적 처치로 얻는 기본 재화는 골드다. 골드는 일반 소환·업그레이드·도박에 사용한다. 처음에는1성3명을 소환할 만큼 지급하고 그 외 초기 용병을 자동 지급하지 않는다. 골드·용병·업그레이드는 전투 안에서만 유지된다.

도박은 **2성 도전과3성 도전이 분리**되고 비용이 다르다. 골드를 지불한 뒤 성공하면 해당 성급 용병을 무작위로 얻는다. 실패하면 보상은 아무것도 없고 지불한 골드는 소모된다. 1성·2성 보정 보상이나 환급을 임의 추가하지 않는다.

성공 풀에는 구현된 해당 성급의 **모든 플레이 가능한 용병**을 포함한다. 교차 조합형·미발견 용병을 임의 제외하지 않는다. 미래 콘텐츠 초안과 현재 플레이 등록 목록은 구분하되 구현된 용병을 숨겨서 풀을 축소하지 않는다. 소환 배치는 일반 소환과 같은 열 우선 첫 빈칸이다.

### D-UPGRADE / T

MVP 업그레이드는 **1~4성 각각의 공통 공격력 강화 네 항목**이다. 방어력 표시는 없고 효과 없는 방어력 강화도 구현하지 않는다. 이는 아군이 피격되지 않는 규칙에 따른 기능 정리용 기본안이다. 적 내부 피해 경감과는 별개다.

성급의 현재·미래 용병 모두 강화 혜택을 받고, 조합 후 결과 성급의 강화를 적용한다. 재료 성급 강화량을 결과에 영구 누적하지 않는다. 개체 영구 레벨 시스템을 만들지 않는다.

가격·성공 확률·증가량·등급 내 가중치·최대 강화 단계 등은 T다. 초기 값 예시는 `data/game_rules.json`에 고정 규칙과 분리되어 있다. 숫자가 변경되면 UI와 판정 데이터를 함께 바꾼다. 연타·다중 입력에도 결제와 결과가 한 거래로 처리되어야 한다.

## 9. 특수몬스터

### F-SPECIAL

특수몬스터는 **보상형 적**이다. 아군을 돕는 소환수·스킬이 아니고 적을 공격하지 않는다. 플레이어가 창에서 선택하면 진행 중인 웨이브에 해당 적 한 마리가 추가된다. 아군36칸을 사용하지 않는다.

10·30·60웨이브를 **완료한 뒤** 각각 해금한다. 소환은 무료, 재소환 가능, 쿨타임은 **5분**이다. 여러 특수몬스터가 동시에 존재할 수 있으며 일반 적·보스·마왕과도 공존한다. 처치하면 대량의 골드, 탈출하면 목숨1 감소다.

### I-UNLOCK / D-COOLDOWN

완료 시점은 고정30초 일정의 종료다. 즉11·31·61웨이브 진입 때 각각 해금한다. 이전 보스가 CC로 남아 있어도 해금한다. '보스 처치'를 별도 조건으로 추가하지 않는다.

종류별 독립 쿨타임300게임초, 소환 성공 시 시작, 정지와 배속을 다른 전투 시간과 같이 적용한다.5배속에서300게임초는60실제초다. 화면에는 항상 게임시간 잔여를 표시하고 필요 시 짧게 설명한다. 앱 종료·백그라운드·설정 정지 중 회복하지 않는다.

같은 종류가 살아 있어도 쿨타임이 끝나면 다시 소환하는 기본안이다. 같은 프레임의 반복 입력은 한 번만 성공한다. 종료된 판·잠금·쿨타임 중에는 생성하지 않는다. 아군 칸이 가득 찬 경우에도 특수몬스터 소환을 막지 않는다.

## 10. 화면·UI·시간 정지

### F-HUD

- **좌상단:** 단일 하트 아이콘 + `× 현재 목숨`. 시작 표기는 `♥ × 20`. 하트를20개 나열하지 않는다.
- **상단:** 웨이브 `12 / 100`, 골드, 필요 시 남은 진행시간.100웨이브에는 강제 종료 카운트다운을 표시하지 않는다.
- **배속:** 버튼 하나. 누를 때마다 `×1 → ×2 → ×3 → ×5 → ×1`. 현재 값만 보여준다.
- **별도 기능:** 일시중지와 설정. 조합법 버튼에 일시중지 아이콘을 붙이지 않는다.
- **우상단:** 가이드, 조합법. 최소 텍스트와 명확한 아이콘을 사용한다.
- **아래 중앙:** 큰 `소환` 버튼과 골드 비용.
- **맨 아래:** 왼쪽부터 `업그레이드`, `도박`, `특수몬스터` 세 버튼.
- 하단 기능창은 소환 버튼 **위에**, 전장 일부를 가리는 오버레이다. 전장을 작게 축소하거나 밀어내지 않는다. 소환과 하단 세 버튼은 남겨둔다.
- 하단 창은 한 번에 하나. 다른 버튼을 누르면 교체. 가린 영역은 전장 입력이 통과하지 않는다.
- 방어력 표기와 불필요한 상시 가이드, 긴 슬로건, 캐릭터별 소환 카드바, 수동 스킬바를 추가하지 않는다.

### F-PAUSE / I-TIME

창을 열어서 전투가 정지하는 것은 **설정 창만**이다. 가이드·조합법·도감·업그레이드·도박·특수몬스터 창은 열려도 전투가 진행된다. 도감이 메인 메뉴에서 열리면 진행 중 시뮬레이션 자체가 없다. 별도 일시중지 버튼과 앱 백그라운드 전환도 전투를 정지한다.

하나의 게임 시간 기준으로 웨이브, 생성, 이동, 공격, CC, 특수몬스터 쿨타임을 진행한다. 렌더 FPS·UI 애니메이션과 분리한다. 단순히 캐릭터 이동에만 배속을 곱하지 않는다.

정지 사유를 독립적으로 관리한다. 사용자가 정지한 뒤 설정을 열고 닫아도 사용자 정지는 유지한다. 백그라운드로 갔다 복귀해도 다른 정지 사유는 해제하지 않는다. 복귀 때 대규모 경과시간을 한 번에 반영하지 않는다.

## 11. 메인·도감·저장·이어하기

### F-SAVE / I-SNAPSHOT

오프라인 플레이. 설정·도감 저장, 도감에는 용병과 모든 적(일반·보스·특수)이 포함된다. 최고 기록과 이어하기도 제공한다. 장기 저장과 전투 스냅샷은 분리한다.

| 데이터 | 생명주기 |
|---|---|
| 설정, 도감 발견/처치 이력 | 판 사이 유지 |
| 최고 도달 웨이브, 클리어 여부 | 판 사이 유지 |
| 현재 판의 상태 스냅샷 | 같은 판 이어하기용. 결과 저장 후 제거 |
| 골드·용병·강화 | 스냅샷에는 포함되지만 새 판에 상속하지 않음 |

스냅샷은 schema/version, content version, run ID, 웨이브·경과시간·다음 생성 사건, 목숨·골드·강화, 용병ID·종류·성급·칸·공격 타이머, 적ID·종류·HP·경로 진행도·소속 웨이브·CC, 특수몬스터 해금·쿨타임, RNG 상태, 필요 시 투사체/예약 피해 등 재개에 필요한 상태를 포함한다. 이미지·노드는 저장하지 않고 정의ID를 참조한다. 단순히 웨이브 번호만 저장해 적을 새로 생성하는 방식은 이어하기가 아니다.

**D:** 일반 진행 자동저장(예: 실제 시간10초, 웨이브 경계 및 상태 변경 후 합치기), 백그라운드 진입, 설정에서 메인으로 복귀, 정상 종료 때 저장한다. 매프레임 디스크 쓰기는 피한다. 마지막 성공 스냅샷부터 복구하므로 강제 종료 직전 미저장 프레임까지 보장하지 않는다. 임시 파일→교체와 마지막 정상 백업 등 안전한 저장 방식을 사용한다.

성공/실패 거래와 저장의 경계를 정리해 골드·재료 중복 복구를 막는다. 읽을 수 없는 저장은 기존 파일을 보존하고 안내하며 이어하기를 비활성화한다. 결과 처리 후 오래된 스냅샷으로 부활하지 않게 run ID/종료 상태를 확인한다.

앱이 꺼진 동안 진행하거나 쿨타임을 줄이거나 골드를 주지 않는다. 새 게임이 진행 중 저장을 덮는 경우 확인한다. 이어하기는 초기에는 정지된 상태로 복원해 사용자가 재개하도록 하는 D안이다.

### D-CODEX

메인 메뉴에는 새 게임, 이어하기, 도감, 설정, 가이드를 둔다. 최고 도달과 클리어 여부는 간결하게 표시한다. 유효 스냅샷이 없으면 이어하기 비활성화.

도감은 용병/적 탭, 적 내 일반/보스/특수 필터를 제공한다. 전략 확인이 필요하므로 기본 명세·조합은 모두 열람 가능하게 하고, 발견 여부만 따로 표시하는 MVP 기본안이다. 미발견이라 조합을 금지하지 않는다. 용병은 최초 소환/조합/도박 성공, 적은 최초 등장 때 발견 처리한다. 도감 수집 보상이나 영구 전투 유닛 소유를 추가하지 않는다. 용병 HP·방어력·영구 레벨·초기 자동 지급 문구를 표시하지 않는다.

## 12. 콘텐츠·리소스·개발

### F-ASSET

공통 계열은 인간형, 중량 인간형, 사족형, 다족형, 부유형, 덩어리형, 용형이다. 색상·헤어·장비·효과를 조립해 재사용한다. 전용 리그를 직업·성급마다 만들지 않는다. 기존 가시여왕은 인간형, 용암거북은 용암거인, 황금 사슴은 황금 고블린, 탑승 도적왕은 도보 두목으로 정리한다. 용은 별도 계열로 유지한다.

MVP는 시스템 목적이므로 초기 완성 아트는 최소로 한다. 먼저 테스트 가능한 모형으로 기능을 구현한 뒤 핵심 외형과 피드백을 개선한다. 34용병·40일반·10보스·3특수는 콘텐츠 초안이며87개 완성 에셋을 먼저 제작할 의무가 없다.

데이터 정의와 시각 리소스 매핑을 분리한다. `data/`에 수록한 전체 카탈로그를 활용하되, 미래 초안과 실제 등록 플레이 데이터를 구분한다. 단계A는 최소 정의로 계약을 검증할 수 있고 이후 가능한 범위에서 전체 정의를 공유 리소스로 확장한다. 실제 제공한 콘텐츠 수와 재사용 범위를 보고한다. 100웨이브 구조 자체를 짧게 축소한 뒤 MVP 완료라고 하지 않는다.

### D-ARCH / QA

시뮬레이션·콘텐츠 데이터·저장·UI·시각 표현을 분리하는 구조를 권한다. 구체 엔진 버전·코딩 언어·렌더러는 현재 실행 환경을 확인하고 프로젝트 기록에 고정한다. 추가 라이브러리는 필요한 만큼만 사용한다.

중요 검증: 좌표·사거리, 열 우선 배치, 시간 일정, CC 중첩, 비용/재료 원자성, 풀등록 도박, 특수몬스터 동시 존재, 마지막 마왕 승패, 여러 정지 사유, 저장/복구, 최신 HUD. 자동 테스트만으로 터치·화면·백그라운드 품질을 통과했다고 주장하지 않는다.

`docs/QA_ACCEPTANCE.md`의 검증을 수행하고 결과를 남긴다. 실제 실행 가능한 산출물과 명령, 알려진 문제, 플레이테스트의 한계를 함께 전달한다.
