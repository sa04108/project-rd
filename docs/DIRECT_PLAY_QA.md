# 직접 플레이와 안정성 통합 검증

2026-10-02 UTC. 기준 main `3624014`에 전투 표현 `5654bfa`와 Web 저장 검사 `4b948fb`를
작업 브랜치에서 통합했다. main 병합과 공개 배포는 수행하지 않았다.

## 수정

- 저장 실패 시 메뉴 전환과 창 종료를 중단하여 살아 있는 전투를 보존한다.
- 앱 포커스와 운영체제 중단의 정지 사유를 분리한다. 하나의 복귀 신호만으로 재개되지 않는다.
- 빈 JSON 저장을 원본 격리 대상으로 처리한다. 같은 칸 이동은 revision을 바꾸지 않는다.
- 수명주기/저장 실패 회귀를 기본 검사에 포함하고, 화면 배율이 다른 창에서도 터치 테스트 좌표를 변환한다.
- 워크플로 수준 자동 취소를 끄므로 후속 실행이 진행 중인 배포를 강제로 취소하지 않는다.
- 기존 통합의 `scripts/verify.sh`는 실제 `mvp-check.sh`를 호출하는 호환 진입점으로 존재한다.

## 직접 실행한 검증

Godot `4.7.2.stable.official.ed1daf0bf`의 공식 다운로드 SHA512를 확인했다.

- `bash scripts/mvp-check.sh`: import, 규칙/저장/아트/전투표현 36개, 수명주기 회귀, 300회 smoke
- 데스크톱의 Godot GUI에서 `tests/ui_scenario.gd`: 185개, 실패 0
- `bash scripts/web-export.sh`: Web 빌드

그래픽 검사는 별도 headless 검사와 구분한다. 데스크톱에서 처음 실행한 UI 검사는 터치 좌표의
배율 누락으로 실패했다. 창 좌표 변환을 추가한 최종 실행에서 185개가 통과했다.

에이전트가 실제 데스크톱 입력으로 새 게임, 일시정지, 3회 소환, 용병 드래그 이동,
전투 재개, 설정, 저장 후 메뉴, 이어하기, 창 종료를 수행하고 화면을 확인했다.
이어하기에서 웨이브2/목숨15/골드180/용병3명과 이동된 위치 및 일시정지가 복원됐다.
이 짧은 플레이를 100웨이브 난이도 검증이나 사람의 첫 클리어율 측정으로 해석하지 않는다.

## 남은 범위

- 로컬 Web 파일은 내보냈으나 이 작업의 Cloud Browser는 localhost 접근을 차단했다.
  그 제한은 우회하지 않았고 네이티브 Godot 실행으로 직접 플레이했다.
- GitHub Pages 최초 활성화 및 공개 URL은 별개다. 이 변경은 이를 활성화하지 않는다.
- Android 물리 기기, Godot 4.7.2 APK 전체 회귀, 실제 음향은 이번 작업에서 검사하지 않았다.
- 작은 설명 글자의 가독성, 고유 프레임 제작, 최종 음향은 추가 작업 대상이다.
- 새 이미지 생성은 수행하지 않았다. sprite-gen 중간 프롬프트 추출 규칙과 최상위 모델 검증 제한은 유지한다.

## 작은 화면 조작부 후속 보강

320px 폭으로 축소했을 때 상단 조작부가 약24~27px였던 문제를 수정했다.
상단 버튼은 우측 3열×2행, 108×100 논리 픽셀로 배치하고 하단 주요 버튼도 높이100으로
확대했다. 320px 폭에서 44px 이상의 입력 영역을 확보한다. 정사각형 전장 좌표와
배경, 좌상단 목숨, 단일 배속 순환, 우측 조합법은 유지한다.
알림 문구는 하단 버튼과 겹치지 않도록 선택 정보 영역에서 잠깐 표시한다.

GUI 검사는 주요 버튼 최소 크기·화면 내 배치·상호 비겹침을 포함해260개 통과했다.
고정20프레임 대기는 빠른 렌더 환경에서 실제 UI 갱신보다 먼저 끝날 수 있어,
구매 가능 상태를 최대1초 동안 관찰하는 방식으로 교체했다. 성공 조건은 유지했다.
최종 배치 렌더를 직접 확인했다. 물리 모바일 기기의 터치 감각과 노치 검증은 별개다.
